# GLAMFLOW v0.3 — Production Data Layer

Implemented foundation:

- PostgreSQL/Prisma schema for multi-tenant SaaS data.
- User, workspace and membership relationships.
- Role-based membership enum.
- Persistent content lifecycle states.
- Social account model for platform integrations.
- Publish job model for asynchronous publishing.
- Audit log model.
- Password hashing and JWT authentication utilities.
- Tenant-aware persistence helpers that require authenticated membership.

## Security rules

1. Do not accept an arbitrary workspace ID as proof of access.
2. Verify membership before every workspace-scoped query/mutation.
3. Keep provider access/refresh tokens server-side and encrypt them before production storage.
4. Set a strong `SESSION_SECRET` in deployment secrets.
5. Add rate limiting, CSRF protection where cookie auth is introduced, request validation and audit events before public launch.

## Next

Connect the API routes to Prisma, add registration/login/session endpoints, create the initial migration, then replace the in-memory content store with transactional PostgreSQL operations and Redis-backed publishing jobs.
